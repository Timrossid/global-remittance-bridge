# 📋 Google Form Feedback Spec & Export Guide

This document specifies the exact Google Form used to collect onboarding + product
feedback for the Global Micro-Remittance Bridge, how to build a prefill URL, and how
to export every response into an Excel (`.xlsx`) sheet committed to this repo.

> **Status:** ✅ **Live.** The public form is published at
> **[https://forms.gle/QgempCFKcho8PwgA7](https://forms.gle/QgempCFKcho8PwgA7)**
> with all 10 required fields. Remaining owner steps: collect 10+ real responses,
> export them to Excel via `export-feedback-to-xlsx.ts`, and register them in the
> README tables.

---

## 1 · Required form fields (Google Form)

Create the form at <https://forms.google.com> with these questions. Match the names
exactly so the prefill parameters and the Excel columns line up.

| # | Question label | Answer type | Options / Format | Required |
|---|---|---|---|---|
| 1 | Name | Short answer | free text | ✅ |
| 2 | Email | Short answer | email | ✅ |
| 3 | Wallet Address | Short answer | `G...` Stellar public key | ✅ |
| 4 | Network | Multiple choice | **Testnet**, **Mainnet** | ✅ |
| 5 | Product Rating | Linear scale | 1–5 | ✅ |
| 6 | Which feature did you like the most? | Paragraph | free text | ✅ |
| 7 | What feature do you think is missing? | Paragraph | free text | ✅ |
| 8 | Did you encounter any bugs or usability issues? | Paragraph | free text (enter "None" if none) | ✅ |
| 9 | Would you recommend this product to others? | Multiple choice | **Yes, definitely** · **Probably** · **Not sure** · **Probably not** · **No** | ✅ |
| 10 | What improvements would you like to see? | Paragraph | free text | ✅ |

> The in-app `/feedback` page (`merchant-dashboard/app/(dashboard)/feedback/page.tsx`)
> already collects exactly these 10 fields, pre-fills Wallet Address/Email/Name from the
> signed-in merchant, and stores responses in `localStorage` + POSTs to the API.
> The Google Form is a parallel survey channel used for the "10+ real users" evidence.

## 2. Live public form link

The public (no-login) form is already live at **https://forms.gle/QgempCFKcho8PwgA7**.
For reference, the settings used to make it public are below so any cloned/rebuilt form
matches the same behavior:

1. Create a new form in Google Forms and add the fields above.
2. In **Settings → Responses**, turn **OFF** "Collect email addresses" (so testers can
   answer without signing in).
3. Under **Settings → Presentation**, turn **OFF** "Show link to submit another response".
4. Write a short intro/title, then click **Send**, choose the link tab, and check
   **Shorten URL**.
5. Copy the short link (e.g. `https://forms.gle/XXXX`). Paste it into the README's
   **Live Links** table as the **Google Form** row.

## 3. Prefill URL builder (optional)

Google Forms supports pre-filled URLs. After step 4, open a fresh response via the
three-dot menu → **Get pre-filled link**, fill a sample, and copy the resulting URL —
it contains `(.../viewform?entry.<NNNN>=...&entry.<NNNN>=...)`. Use the script below to
generate a prefill URL per tester (e.g. to embed in a "leave feedback" email):

```bash
# Replaces placeholders with real values. Field ids come from your form's
# "Get pre-filled link" URL: entry.1234567890 -> Name, entry.1234567891 -> Email, ...
node build-feedback-prelink.js \
  --form "https://docs.google.com/forms/d/e/YOUR_FORM_ID/viewform" \
  --map "name=entry.1234567890,email=entry.1234567891,wallet=entry.1234567892,network=entry.1234567893,rating=entry.1234567894" \
  --name "Jane" --email "jane@x.com" --wallet "GABC..." --network "Testnet" --rating "4"
```

The prefill URL is generated by the helper at
[`payment-api/scripts/build-feedback-prelink.js`](../payment-api/scripts/build-feedback-prelink.js).

## 4. Export responses to Excel

### Option A — Google Forms → Sheet → export (recommended for the public form)

1. Open the Google Form → **Responses** tab → green **Link to Sheets** icon.
2. Create / link a Google Sheet (this gives a public, shareable URL).
3. **Share** the Sheet → under "General access" choose **Anyone with the link → Viewer**
   (this produces a public link for the README).
4. In the Sheet: **File → Download → Comma-separated values (.csv)**.
5. Convert to `.xlsx` (optional) and run the repo export script to normalize columns:

```bash
cd payment-api
# Pull responses from the API into a JSON export, then to xlsx:
npx tsx scripts/export-feedback-to-xlsx.ts --json feedback-responses.json -o feedback-responses.xlsx
```

### Option B — in-app feedback → API → Excel

Responses submitted through the dashboard `/feedback` page are POSTed to
`POST /feedback` and stored in the `Feedback` Prisma table. Export straight from the
database:

```bash
cd payment-api
npx tsx scripts/export-feedback-to-xlsx.ts --db -o ./exports/feedback-responses.xlsx
```

This produces a `.xlsx` with the columns: **ID, Submitted At, Name, Email, Wallet
Address, Network, Rating, Liked most, Missing feature, Bugs/issues, Recommend?,
Improvements**.

## 5. Wire the public form into the dashboard

Set `NEXT_PUBLIC_FEEDBACK_FORM_URL` in your Vercel deployment to the public Google Form
link. The `/feedback` page then renders a "Fill out our Google Form ↗" link in its
footer, giving testers both the inline form and the survey link.
